Component · Actions

Button

Buttons start an action: buy, list an item, ship, save. One ink primary button per screen tells the member what matters most.

Overview

Use a button when activating it changes something: it submits a form, opens a dialog, reserves an item or saves a draft. Use a link when it only takes the member somewhere (a listing, a seller's profile). Several related actions behind one trigger are a menu.

  • Primary (solid ink, bold label) is the one action the screen exists for: Buy now, List item, Pay $94.00. Never two per view.
  • Secondary (the default look, outlined) is for every other action: Make an offer, Cancel, Save draft.
  • Ghost sits in dense places: the top bar, dialog close buttons, card and row actions.
  • Link looks like a link but is a button: Show more reviews inside text.
  • Danger confirms a destructive action (Withdraw listing, Close account) and appears only inside a confirmation dialog.

Anatomy

  1. Leading icon (optional)1.25em square, 2px stroke, inherits the label colour, aria-hidden.
  2. LabelA verb phrase in sentence case. It is the accessible name. Primary labels are bold.
  3. ContainerHeight from --control-height-*, --radius-md (2px) corners, 1px border, padding from the spacing scale.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this screen.

Emphasis from highest to lowest; danger only appears inside confirmation dialogs.
HTML
<button class="btn btn--primary" type="button">Buy now</button>
<button class="btn" type="button">Make an offer</button>
<button class="btn btn--ghost" type="button">Close</button>
<button class="btn btn--link" type="button">Show more reviews</button>
<button class="btn btn--danger" type="button">Withdraw listing</button>

Sizes

Medium (40px) is the default. Small (32px) lives in toolbars, uploader tiles and row actions. Large (48px) is for the buy bar, auth screens and the hero, where the button is the point of the screen.

Heights --control-height-sm/md/lg; padding --space-3/4/6; label --font-size-sm/md/lg.
HTML
<button class="btn btn--primary btn--sm" type="button">Small</button>
<button class="btn btn--primary" type="button">Medium</button>
<button class="btn btn--primary btn--lg" type="button">Large</button>

States

Every variant has the same six states. Hover, focus and active are forced here with data-state so they can be reviewed without a pointer; real pages get them from :hover, :focus-visible, :active, disabled and aria-busy.

Both themes

  • Loading keeps the width, hides the label behind a spinner, sets aria-busy="true" and ignores clicks. In the mocks: Pay $94.00 while the card is charged, Publishing… on the sell form, dialog confirm buttons while they save.
  • Disabled uses the native attribute: not focusable, 50% opacity. Prefer leaving the button enabled and explaining the problem on submit (the sell form shows an error summary instead of a dead List item button).
  • Pressed toggles use aria-pressed; see button group. Expanded menu triggers use aria-expanded; see menu.

Responsive behaviour

  • Below 640px the primary action of a form or dialog becomes full width (.btn--block) and sits last, under the secondary action.
  • On listing detail below 1024px, Buy now and Make an offer move into the sticky buy bar as large block buttons; from 1024px they sit in the info column.
  • In dialog footers buttons stay on one row and wrap when the row is too narrow; the primary stays last (rightmost, or bottom when wrapped).
  • The top bar's Sell action is a nav link from 768px and moves into the menu sheet below it.
  • Labels never truncate. A label that wraps at 360px is too long; shorten the verb phrase.

Theming

The button reads semantic tokens through five component tokens that each variant overrides: --btn-bg, --btn-fg, --btn-border, --btn-bg-hover and --btn-bg-active. A theme changes the semantic tokens; a surface re-skin overrides the component tokens; neither edits .btn.

/* Buttons on an inverse surface (cookie consent) flip to paper on ink: */
.consent .btn         { --btn-bg: transparent; --btn-fg: var(--color-fg-inverse); --btn-border: var(--color-border-inverse); }
.consent .btn--primary { --btn-bg: var(--color-fg-inverse); --btn-fg: var(--color-bg-inverse); --btn-border: var(--color-fg-inverse); }

In the dark theme the accent becomes paper, so the primary button is paper with an ink label (the logo inverted), and the danger button lightens to --palette-red-300 with a deep-red label. Both pairs stay above 7:1.

Accessibility

Role and pattern

Native <button type="button">, or type="submit" inside a form. A link styled as a button (Sign in in the top bar) stays an <a href>. Never a <div> with a click handler. No ARIA role is needed.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
Enter, SpaceActivates the button. Space fires on key up, so a mis-press can be cancelled by moving away.
EscNo effect on the button. A loading button cannot be cancelled with Esc; long actions offer a separate Cancel.

Focus

The shared ring (2px --color-focus-ring, 2px offset) appears on :focus-visible only. Ink on paper in light and paper on ink in dark, so it reaches 3:1 against the page and the button in both themes.

Labelling

The visible label is the accessible name. Icon-only buttons set aria-label with a verb and object (Remove photo 2, Close). Loading buttons keep their name and add aria-busy="true"; progress text is announced by the form's live region, not the button.

Motion

Background, border and shadow transition over --duration-fast (120ms); active nudges down 1px. Both disappear under prefers-reduced-motion because the tokens zero the durations. The loading spinner keeps turning: it is a status, not decoration.

Touch

Medium (40px) and large (48px) clear the 24px minimum; large meets the 44px comfortable target and is used for the buy bar and auth forms. Small (32px) only appears with 8px between neighbours.

Content

  • Verb phrases in sentence case: Buy now, List item, Add tracking, Confirm receipt. Never OK, Yes, Submit or Click here.
  • Put the amount in payment buttons: Pay $94.00. The member sees exactly what they agree to.
  • Destructive labels name the loss: Withdraw listing, Close account, not Confirm.
  • The safe option says what it keeps: Keep listing, Keep order, rather than a bare Cancel when Cancel is ambiguous (as in Cancel order dialogs).
  • Keep labels to three words where possible; loading never changes the label.
