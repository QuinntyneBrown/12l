Inline message

Small text next to the thing it is about: a field hint or error, a saved status, the reservation countdown, the secure-payment note.

WCAG 2.2 AAStatus: stableLinked with aria-describedby

Overview

Inline messages are the quietest feedback: one line beside a control or in a panel. They never interrupt and never float. Use them when the message belongs to exactly one element. For a message about a whole form use an alert (error summary); for a passing confirmation a toast.

  • Field hint (.field__help): what to enter, before the member types (At least 10 characters.).
  • Field error (.field__error): what to fix, with a ⚠ marker so it is not colour alone (Enter a price from $1.00 to $5,000.00).
  • Inline status (.inline-status): the result of a small action in place (Saved, Checking your link…).
  • Reservation timer (.timer): the checkout countdown, neutral then warning under a minute, danger at zero.
  • Secure note (.secure-note): reassurance under the card field (Card details go straight to our payment provider. 12L never sees them.).

Anatomy

  1. LabelThe field's name; see form field.
  2. ControlMarked aria-invalid when the error shows.
  3. Hint--text-body-sm, muted, always visible.
  4. Error--text-body-sm in --color-danger-fg with a ⚠ marker; below the hint.

  • Errors appear on submit and on blur after the first edit, and clear as soon as the value is valid (see forms).
  • The timer turns warning at 1:00 and danger at 0:00, when the pay button is disabled and a banner explains what happened.

Responsive behaviour

  • Messages wrap under their control at every width; they never sit beside a field on phones.
  • The timer sits above the pay button in the order panel; on phones it stays visible next to the sticky pay action.
  • Long errors wrap with a hanging indent so the ⚠ marker stays on the first line.

Theming

Inline messages use semantic text tokens directly: --color-fg-muted for hints and neutral status, --color-danger-fg for errors, --color-success-fg and --color-warning-fg for status. No component tokens are needed; the dark theme lightens each status foreground to its 300 step.

Accessibility

Role and pattern

Hints and errors are linked to their control with aria-describedby (hint id first, then error id), and the control gets aria-invalid="true". The checkout timer uses role="timer" with aria-live="off" so it is not read every second; the warning and danger banners announce the important moments instead. An inline status inserted after an action sits in a role="status" container.

Keyboard

Inline messages are not interactive. Links inside them (rare) are reached with Tab.

Focus

No focus of their own. On a failed submit focus goes to the error summary, which links to each field; the field's own error is then read with it.

Labelling

Errors name the fix, not the rule that failed. The ⚠ marker is CSS content; the error text carries the meaning. Icons in statuses are decorative.

Content

  • Hints say what is expected before it goes wrong: Shown on the listing. At least 10 characters.
  • Errors are imperative and specific: Enter a price from $1.00 to $5,000.00, Describe the item's flaws, Confirm the label shows men's US 12.
  • Status is one or two words: Saved, Checking your link… (with an ellipsis while busy).
  • Timer: Reserved for you · 9:41 left, minutes and seconds in tabular numerals.
