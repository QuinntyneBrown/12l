Sidebar navigation

A vertical list of grouped links for sections a member moves between often. Part of the core kit; no 12L mock uses it yet.

WCAG 2.2 AAStatus: stableCore (not in mocks)

Overview

The mocks put account sections in horizontal tabs (the account sub-nav) because there are only eight of them and the content needs the width. The sidebar is documented from .sidebar in components.css for when a section outgrows tabs, for example a future seller dashboard or admin console with more than eight destinations. Until then, prefer tabs for account screens and the top bar for everything global.

  • Use it for 6–20 destinations in named groups.
  • Do not use it for actions; actions are buttons in the page header.
  • Do not combine it with sub-nav tabs for the same level of hierarchy.

Anatomy

  1. Group labelOverline, --color-fg-subtle, not focusable.
  2. Icon20px, aria-hidden.
  3. LinkFull-width nav link, 44px tall; current gets the brand bar.

Responsive behaviour

  • Hidden below 1024px; the page shows a menu button that sets data-open="true" to reveal it as an overlay.
  • From 1024px it sits in a .sidebar-layout grid column, sticky and full height, scrolling on its own.

Theming

Surface background with a hairline right edge. Links reuse .nav-link, so they theme exactly like the top bar: muted text, subtle hover, brand bar for the current page.

Accessibility

Role and pattern

A <nav aria-label> landmark of links; group labels are paragraphs (or headings when the groups are long). Not an APG tree or menu.
