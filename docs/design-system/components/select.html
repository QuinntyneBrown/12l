Select

A native drop-down for one answer from a fixed list: category, type, state, country, carrier, sort order.

WCAG 2.2 AAStatus: stableNative <select>

Overview

Use a select for 5–15 known options where the member knows the answer (their state, the carrier). Under five options that deserve comparison, use a radio group or segmented button group. 12L uses the native element everywhere: it gets the platform picker on phones, type-ahead and full accessibility for free. A custom listbox is only justified when options need rich content.

  • Placeholder option (Choose a category, value="") when there is no safe default; validation treats it as empty.
  • Dependent: Type is disabled until Category is chosen on the sell form.
  • Toolbar sort: small, with a quieter edge, labelled by a visible Sort prefix.

Anatomy

  1. Selected value--text-body; the placeholder option reads as a value, so the field label must carry the question.
  2. ChevronDrawn with two gradients in currentColor, 40px reserved on the right (--space-10).

Responsive behaviour

  • Full width in forms; auto width in toolbars.
  • On phones the OS picker replaces the drop-down list; nothing to design there.
  • State and ZIP share a row from 640px on the address form.

Theming

Shares --field-* tokens with text fields. The chevron uses currentColor, so it follows --field-fg in both themes. Toolbars override --field-border with --color-border-default.

Accessibility

Role and pattern

Native <select> with <label for>; errors via aria-describedby and aria-invalid. If a custom listbox is ever needed, it follows the APG Select-Only Combobox.

Content

  • Placeholder options start with a verb: Choose a category, Select a state.
  • Order options logically (alphabetical states; categories in catalog order), not by internal id.
  • Show the current sort in the selected option text; no separate label needed beyond Sort.
