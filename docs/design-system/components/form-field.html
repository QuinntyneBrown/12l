Form field

The wrapper every input sits in: label, optional marker, control, help, error and counter, always in that order and spacing.

Overview

Every text field, textarea, select and single checkbox is wrapped in a .field. It fixes the vertical rhythm (--space-1 between parts) and wires the accessibility: for/id, aria-describedby and aria-invalid.

  • Help text appears before the error; both can show at once.
  • Only optional fields are marked, with (optional) in subtle text.
  • The counter is last and right-aligned.

Anatomy

  1. Label--text-label, --color-fg-default.
  2. ControlAny input; carries aria-describedby and aria-invalid.
  3. Help--text-body-sm, muted.
  4. Error--text-body-sm, --color-danger-fg, with a warning glyph.
  5. CounterCaption, subtle, right-aligned.

Responsive behaviour

  • Fields fill their column; in .form-row two fields sit side by side from 640px.
  • Error and help text wrap; never truncate them.

Theming

Help reads --color-fg-muted, errors --color-danger-fg, the optional marker and counter --color-fg-subtle. All pass 4.5:1 on canvas, surface and raised surfaces in both themes.

Accessibility

Role and pattern

<label for> plus aria-describedby listing help then error ids; aria-invalid="true" on the control when the error shows. Choice fields use <fieldset>/<legend> instead of a label.

Keyboard

The wrapper adds no keyboard behaviour; see the control's page.

Focus

On submit with errors, focus goes to the error summary, whose links move focus to each field.

Labelling

Errors say what to do, are shown under the field and in the summary, and are announced via the summary's role="alert".

Content

  • Error formula: what to do, not what went wrong: Enter a price from $1.00 to $5,000.00.
  • Mark optional fields, not required ones.
  • Help text is one sentence; rules belong there, not in the error alone.
