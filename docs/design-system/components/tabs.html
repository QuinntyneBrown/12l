Tabs

Tabs switch between views of the same thing (listing statuses) or between sibling pages (the account sub-nav). The selected tab carries the red bar.

Overview

Two variants share one look:

  • Tab panel: buttons with role="tab" that swap content on the same page without a URL change. Use for filtered views of one collection.
  • Link tabs (.subnav): real links with aria-current="page" that go to sibling pages. The account area uses these: Overview, Listings, Purchases, Sales, Payouts, Profile, Emails, Settings.

Use link tabs whenever each view deserves its own URL. Use a button group for a setting, not a view.

Anatomy

  1. Tab label--text-label, muted until selected.
  2. Count (optional)A neutral badge.
  3. Selected bar3px --color-brand over the hairline baseline.

Responsive behaviour

  • Tabs never wrap; the list scrolls horizontally (scrollbar hidden) and the selected tab is scrolled into view on load.
  • At 360px the account sub-nav shows about four tabs; the cut-off fifth tab signals that it scrolls.
  • Labels never truncate.

Theming

Labels use --color-fg-muted, turning --color-fg-default on hover and selection. The baseline is --color-border-default; the selected bar is --color-brand in both themes.

Accessibility

Role and pattern

Tab panel: APG Tabs with role="tablist", role="tab", role="tabpanel", roving tabindex and automatic activation (arrow keys select). Link tabs: a <nav aria-label="Account"> of links with aria-current="page"; no tab roles.

Keyboard

KeyAction

← / →Tab panel: select the previous / next tab (wraps).

Focus

Shared ring around the tab; the selected bar stays visible under it.

Labelling

The tablist has an aria-label (Listing status); each panel is labelled by its tab. Counts are part of the tab's name (Sold 19).

Motion

Touch

Each tab is 44px tall with 12px side padding.

Content

  • One or two words, nouns: Purchases, Payouts. The account email-preferences tab is Emails, not Notification settings.
  • Counts go in a badge, not in brackets.
