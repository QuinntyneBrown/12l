Component · Inputs

Text field

A single-line input for short answers: email, display name, title, price, tracking number. Always inside a form field with a visible label.

WCAG 2.2 AAStatus: stableNative <input>

Overview

Use a text field for one line of free text. Use a textarea for more than a sentence, a select when the answer comes from a short fixed list, and a radio group when the member should see every option. The field is the bare control; the label, help, error and counter around it come from form field.

  • Text, email, password: set the right type, autocomplete and inputmode so phones show the right keyboard and password managers work.
  • Money (.input-group with a $ addon and inputmode="decimal"): price on the sell form, the price range in filters.
  • Search (.search): the top-bar search with a leading icon and a visually hidden label.

Anatomy

  1. Addon (optional)Unit or prefix on --color-bg-subtle, --text-body-sm, muted. Not focusable.
  2. Value--text-body (16px, so iOS does not zoom); placeholder in --color-fg-subtle only as an example, never as the label.
  3. Container40px (--control-height-md), 1px --color-border-strong edge, 2px corners, --space-3 side padding.

Sizes

Medium (40px) everywhere in forms. Small (32px, .input--sm) only in toolbars (sort, audit-log filter). Large (48px, .input--lg) for the one-time code on verify screens.

  • Invalid (aria-invalid="true") doubles the edge in danger red; the message under the field says what to do.
  • Read-only is used while a form submits (the register and profile forms) so values stay readable and selectable; it switches to the sunken background.
  • Disabled is rare: a field that cannot apply yet (Type until a Category is chosen on the sell form).
  • Required is the default; only optional fields are marked, with (optional) in the label.

Both themes

Responsive behaviour

  • Fields are full width of their column at every breakpoint; the form column caps line length (.page--form, 44rem).
  • Two short fields share a row from 640px (.form-row); below that they stack.
  • Input text stays 16px on phones so iOS Safari does not zoom on focus.
  • The top-bar search is a field from 1024px and an icon button that opens search below it.

Theming

Component tokens --field-bg, --field-fg, --field-border, --field-border-hover and --field-border-invalid alias the semantic tokens; override them on a container to re-skin fields (the toolbar sort uses a quieter edge).

.sort .select { --field-border: var(--color-border-default); }

Accessibility

Role and pattern

Native <input> with a visible <label for>. Help and error text are linked with aria-describedby; invalid fields set aria-invalid="true". The password toggle is a button with aria-pressed and the label Show password.

Keyboard

KeyAction
TabMoves into the field; the addon is skipped.
TypingEdits the value. Arrow keys, Home and End move the caret.
EnterSubmits the enclosing form (forms validate and focus the error summary).

Focus

Focus replaces the edge with the 2px ring at 0 offset so the box does not grow. It is visible on paper and on ink.

Labelling

Every field has a visible label; search is the only exception and carries a visually hidden one. Placeholders are examples, never labels. Use autocomplete tokens (email, username, new-password, street-address).

Motion

Touch

40px tall and full width, well over the 24px minimum; the password toggle is a 40px square.

Content

  • Labels are nouns in sentence case: Display name, Tracking number.
  • Put format rules in help text before the member types: 3–30 letters, numbers, _ or -. Shown publicly.
  • Units go in an addon ($), not in the label.
  • Never use placeholder text for instructions.
