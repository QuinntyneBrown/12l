Menu

A menu button opens a short list of actions or choices: Manage on a listing you own, More actions on a row, Sort on the catalog toolbar.

Overview

Use a menu when one trigger offers three to seven related actions and showing them all as buttons would crowd the screen, typically on phones or in list rows. Do not use a menu for navigation between pages (use tabs or the top bar), or for a form value that must submit (use a select).

  • Action menu: verbs that act on one object (Edit listing, Share, Withdraw listing). A destructive item is last, separated, in danger text, and opens a confirmation dialog.
  • Choice menu: checkable items (menuitemradio) that change a view setting immediately, such as sort order.

Anatomy

  1. TriggerA button with a chevron, aria-haspopup="menu" and aria-expanded.
  2. Item32px tall (--control-height-sm), 16px icon, --text-body-sm label; whole row is the target.
  3. Disabled itemaria-disabled="true"; stays focusable so it can be discovered, in --color-fg-disabled.
  4. Divider and danger itemA separator isolates the destructive item, which uses --color-danger-fg.

Variants

Panels are --color-bg-surface-raised with --shadow-3, 2px corners and a 4px inner padding. They open below the trigger, aligned to its start edge, and flip above when there is no room.

  • Sort by
Action menu with icons, divider and danger item · choice menu with a section label and checked item · icon-only trigger with a shortcut hint.

Sizes

Menus have one size: 32px items with a 12rem minimum width that grows to the longest label.

States

Action menu
  • Disabled item: Download photos above, while the photos are still processing.
  • Checked item: the current sort order, marked with a tick and aria-checked="true".
  • Trigger expanded: aria-expanded="true" while the menu is open; the trigger keeps its hover background.

Both themes

Responsive behaviour

  • On phones (below 640px) an action menu with more than four items opens as a bottom sheet (drawer) instead of a floating panel, so items get 44px rows.
  • The panel never exceeds the viewport: max-width: min(20rem, 100vw - 2 × --layout-margin); long labels wrap rather than truncate.
  • Row menus in lists stay visible on touch devices (no hover-only reveal).

Theming

The panel reads --color-bg-surface-raised, --color-border-default and --shadow-3; in the dark theme the raised surface is one step lighter than the page (ink-850 on ink-950) and the shadow darkens, so the panel still reads as floating. Item hover uses --color-bg-subtle.

.menu { --menu-min: 12rem; min-width: var(--menu-min); }

Accessibility

Role and pattern

WAI-ARIA APG Menu Button: trigger button with aria-haspopup="menu", aria-expanded and aria-controls; panel role="menu" with an accessible name; items role="menuitem" (or menuitemradio/menuitemcheckbox) with roving tabindex; dividers role="separator".

Focus

Focus moves into the menu on open and back to the trigger on close. The focused item shows --color-bg-subtle plus the ring when reached by keyboard.

Labelling

The trigger names the object when it is icon-only (More actions for Arizona sandals). The panel is labelled by the trigger or an aria-label. Shortcuts are shown in a <kbd> and exposed with aria-keyshortcuts.

Motion

The panel scales in from 96% and fades over --duration-fast with --ease-enter; it closes instantly. Reduced motion removes the scale.

Touch

Items are 32px tall with the full row as target in floating menus; the bottom-sheet form on phones uses 44px rows.

Content

  • Items are verbs with the object when it is not obvious: Edit listing, Withdraw listing, Copy link.
  • Order by frequency; destructive last, after a divider.
  • An item that opens a dialog does not need an ellipsis; the dialog title confirms it.
  • Choice menus show the current value in the trigger: Sort: Newest.
