Toast

Toasts confirm that something just happened (Listing published, Payment confirmed) or that a background request failed, without taking the member off the page.

WCAG 2.2 AAStatus: stablerole="status" region

Overview

A toast is a short, temporary message on the inverse (ink) surface, bottom right on desktop and full width at the bottom on phones. Use it for the result of an action the member just took, when the page itself does not show the change. Use an alert when the message belongs to a part of the page and must stay (a declined card, a suspended account); use a page banner (see alert) for conditions that last (offline, maintenance); use a dialog when the member must decide.

  • Info: neutral news (Draft saved, Drafts older than 90 days are deleted).
  • Success: the action worked (Listing published, Payment confirmed, Back online).
  • Warning: something needs doing soon (Ship by Fri 30 Oct, with Add tracking).
  • Danger: a request failed (Something went wrong, Ref 3c8e-1d42-a7f0, Try again). Error toasts never auto-dismiss.

Rules for which feedback to use live in notifications and feedback and loading.

Anatomy

  1. Status edge3px leading rule in the tone colour on ink (--toast-edge); the brand red when untoned.
  2. Icon20px tone icon: info, check-circle, alert, x-circle. Paired with text, never alone.
  3. Title--text-label, one line: what happened.
  4. Text and action (optional)--text-body-sm detail; one underlined text button (Undo, View listing, Try again).
  5. Dismiss24px .close button labelled Dismiss; always present.
  6. Timer bar2px .toast__progress showing time left before auto-dismiss; absent on danger toasts.

Variants

The tone changes the icon and the leading edge; the surface stays ink in light and paper in dark so toasts read as one family above any page.

Sizes

Toasts have one size: 24rem wide from 640px, full width minus the page margin below it.

States

Toasts enter with slide-up over --duration-base, stay 5 seconds (8 with an action), pause while hovered or focused, and leave with fade-out (data-state="leaving"). Hover and focus are forced with data-state.

  • Paused: the timer bar stops while the pointer is over the toast or focus is inside it, so an Undo is never pulled away mid-reach.
  • Persistent: danger toasts have no timer and stay until dismissed or the request succeeds on Try again.
  • Leaving: fades and drops 8px; the region closes the gap without animation.

Responsive behaviour

  • Below 640px the region spans the viewport with a 16px margin and sits above the sticky buy bar and form action bars, never over them.
  • From 640px the region is 24rem wide, 24px from the bottom-right corner.
  • Text wraps; titles do not truncate. On phones keep the detail to one line by naming the item, not describing it.
  • With the on-screen keyboard open, toasts wait until it closes rather than covering the field.

Theming

Component tokens: --toast-bg (--color-bg-inverse), --toast-fg (--color-fg-inverse) and --toast-edge, which each tone points at --color-inverse-info|success|warning|danger. Those inverse tokens exist because the regular status icons are tuned for light surfaces: on ink the tone uses the 300 step, on paper (dark theme) the 700 step.

.toast--success { --toast-edge: var(--color-inverse-success); }
.toast--success .icon { color: var(--color-inverse-success); }

Accessibility

Role and pattern

One .toast-region per page with role="status" aria-live="polite", present in the DOM from page load (empty) so screen readers register it. Toasts are inserted into it and announced politely. Danger toasts carry role="alert" so the failure interrupts. Toasts never take focus.

Keyboard

KeyAction
TabReaches the toast's action and Dismiss button in DOM order (the region sits at the end of <body>).
Enter, SpaceRuns the action or dismisses.
EscDismisses the toast that holds focus.
F6(Recommended in the app) jumps focus into the region when a toast with an action is showing.

Focus

Focus inside a toast pauses its timer. The ring uses --color-fg-inverse on the ink surface so it stays visible (3:1+) against the toast itself.

Labelling

The title and text are the announcement; keep the important words first. Dismiss is aria-label="Dismiss". The timer bar is aria-hidden. Actions repeat the object when it is not in the title (View listing, not View).

Motion

Enter slide-up 16px over --duration-base with --ease-enter; leave over --duration-base with --ease-exit. Under reduced motion toasts appear and disappear without movement. Auto-dismiss times are long enough to read (WCAG 2.2.1): 5s, 8s with an action, never for errors.

Touch

The Dismiss button is 24px (the minimum) with 12px clear around it; the action is a full-height text button. Swiping a toast away is an enhancement, never the only way.

Content

  • Title says what happened in past tense or a short fact: Listing published, Draft saved, Back online. No exclamation marks.
  • Detail names the item or amount: $94.00 charged to Visa ending 4242., Arizona sandals.
  • One action at most, a verb: Undo, View listing, Add tracking, Try again.
  • Errors say it failed and give the reference: Something went wrong · Ref 3c8e-1d42-a7f0.
  • Never put information only in a toast that the member needs later; it disappears. See content and tone.
