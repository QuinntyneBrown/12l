Dialog

A modal window for one short task or one decision: add tracking, cancel a sale, withdraw a listing. On phones it rises from the bottom as a sheet.

WCAG 2.2 AAStatus: stableAPG Dialog (modal)Bottom sheet below 640px

Overview

Use a dialog when the member must finish or dismiss something before going on, and the task fits on one screen: a confirmation, a form of one to four fields. Anything longer is a page; filters and the mobile menu are sheets; a quiet result is a toast. See dialogs and overlays.

  • Form: add tracking, change password, report a problem. Primary action names the result (Add tracking).
  • Destructive: a danger icon, a question title, a description of what will happen and a danger confirm button. The safe button is first and takes initial focus.
  • Small (24rem) for one-line confirmations such as Got it and all good?; large (48rem) for the cookie and resolution dialogs with long content.

Anatomy

  1. Icon (destructive only)40px square, danger tint; aria-hidden.
  2. Title and descriptionh3-size title is the accessible name; the description is linked with aria-describedby.
  3. Close buttonGhost icon button, Close.
  4. Body16px × 24px padding; stacks fields with 16px gaps.
  5. FooterHairline top edge, sticky, actions right-aligned with the primary last.

Sizes

Width is the only size; height follows content up to the viewport minus 48px, then the body scrolls and the footer stays pinned.

States

Dialogs show the same states as forms. Each is a real mock:

StateWhat changes
DefaultInitial focus on the first field, or on the safe button in destructive dialogs.
InvalidErrors under each field (aria-invalid + aria-describedby); focus moves to the first invalid field. The dialog stays open.
BusyThe primary button shows the spinner with aria-busy="true"; other controls stay enabled; Esc and Close still work.
FailedA danger alert under the header says nothing changed; the primary becomes Try again.
SuccessThe dialog closes and a toast confirms, or (when there is more to say) the body is replaced by a success message with one Done button.

Responsive behaviour

  • Below 640px the dialog is a bottom sheet: full width, 6px top corners (--radius-xl), rising from the bottom edge so the actions sit near the thumb.
  • From 640px it is centred with 24px of space around it, 4px corners, and scales in.
  • Footer buttons wrap; when they wrap the primary is on its own row at the bottom. Below 640px consider .btn--block for both.
  • The body scrolls; the header and footer stay visible.

Theming

The panel is --color-bg-surface-raised with --shadow-4 over a --color-bg-backdrop scrim (55% ink in light, 70% black in dark). In dark the raised surface (ink-850) is lighter than the page behind it, so the panel still reads as on top. Component tokens: --dialog-bg, --dialog-shadow, --dialog-max.

Accessibility

Role and pattern

APG Dialog (modal): role="dialog", aria-modal="true", aria-labelledby the title and aria-describedby the description. The page behind gets inert. A native <dialog> opened with showModal() is an equivalent implementation.

Keyboard

KeyAction
Tab / Shift+TabCycles through the dialog's controls only; focus is trapped.
EscCloses the dialog (also while busy; the request continues and its result arrives as a toast).
EnterIn a form dialog, submits.

Focus

On open, focus goes to the first field, or to the safe button in destructive dialogs (autofocus on Keep listing). On close it returns to the control that opened the dialog. On an invalid submit it moves to the first invalid field.

Labelling

Title is the name; the description says what will happen. The close button is Close. Destructive titles are questions that name the object: Withdraw this listing?

Contrast

Text on panel
Description
Field error in dialog
Danger icon on tint

Motion

Backdrop fades in over --duration-base; the panel scales in (or slides up as a sheet) over --duration-slow with --ease-enter. Under reduced motion both are instant.

Touch

Footer buttons are 40px tall with 12px between them; the close button is 40px.

Content

  • Title: a question for decisions (Cancel this sale?), a verb phrase for tasks (Add tracking).
  • Description: one or two sentences with the consequence and the numbers: tall_tom is refunded $48.15 in full.
  • Buttons name outcomes: Keep sale / Cancel sale, never No / Yes.
  • Failure copy: That didn’t go through + Nothing changed. Check your connection and try again.
