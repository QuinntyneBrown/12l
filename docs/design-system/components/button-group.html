Button group

A set of mutually related choices shown side by side: the condition picker on the sell form and the problem type in Report a problem are segmented groups.

WCAG 2.2 AAStatus: stablefieldset + radiosaria-pressed toolbar

Overview

Use a segmented group when the member picks exactly one of two to six short options and every option should be visible at once: the five conditions on the sell form, the three problem types in Report a problem. With more than six options, or long labels, use a radio group (a vertical list) or a select. To filter a list by status, use filter chips, which can wrap and carry counts.

  • Segmented (.segmented) is built from real radio inputs inside a <fieldset>. It is a form control: it submits a value and shows errors like any field. This is the 12L default.
  • Toolbar (.btn-group) joins buttons that toggle a view setting immediately with aria-pressed. It never submits a form.

Anatomy

  1. LegendThe question, as a <legend> in --text-label. It names the group for assistive technology.
  2. Selected segmentSolid ink (--color-accent) with a paper label, the same treatment as a primary button.
  3. Segment44px tall (--target-comfortable), 1px --color-border-strong edge, square corners, --space-2 between segments so they wrap cleanly.

Variants

Segmented groups wrap onto more lines on phones; toolbars stay on one line and are only used for short, single-word options.

Sizes

Segments have one size: 44px tall so they meet the comfortable touch target without a size switch. Toolbar buttons use the small button size (32px) because they sit in dense filter bars; use .btn without --sm when the toolbar is the main control on the screen.

Responsive behaviour

  • Segmented groups use flex-wrap: at 360px the five conditions wrap onto three lines, each segment keeping its full label. Never truncate or abbreviate a condition.
  • When a group would need more than three lines at 360px, switch to a radio group.
  • Toolbars do not wrap; keep them to four short labels, and scroll the filter bar horizontally on phones rather than squeezing it.

Theming

Segments read --color-bg-surface, --color-border-strong and, when checked, --color-accent with --color-fg-on-accent, so the dark theme inverts them to paper segments with ink labels. Toolbar buttons use the button tokens; the pressed one switches to --color-accent-subtle with an --color-accent edge.

/* A quieter segmented group for a filter sheet */
.filter-sheet .segmented input:checked + span { background: var(--color-accent-subtle); color: var(--color-fg-accent); }

Accessibility

Role and pattern

Segmented: native radio inputs in a <fieldset> with a <legend> (the APG Radio Group behaviour comes from the browser). Toolbar: role="group" with an aria-label, each button a toggle with aria-pressed.

Keyboard

KeyAction
TabSegmented: moves into the group onto the checked radio (or the first), then out. Toolbar: visits each button.
← → / ↑ ↓Segmented: moves the selection to the previous or next option and checks it.
SpaceSegmented: checks the focused option. Toolbar: toggles the focused button.
EnterToolbar: toggles. Segmented: submits the form, as radios do.

Focus

The input is visually hidden, so the ring is drawn on the segment (input:focus-visible + span) with the shared 2px ring and 2px offset.

Labelling

The legend names the group (Condition); each segment's text names its option. Errors are linked with aria-describedby on the fieldset. Toolbar groups need an aria-label because they have no legend.

Motion

Background changes over --duration-fast; nothing moves. Reduced motion zeroes the transition.

Touch

Segments are 44px tall with 8px between them, so each is a comfortable target on its own.

Content

  • Labels are the answer, not a sentence: Used - Good, Damaged. Keep each to three words.
  • Use the same casing and wording the rest of the product uses for the value (condition names match listing cards and filters exactly).
  • The legend asks the question: Condition, What’s wrong?
  • Do not preselect an option when the member must make a deliberate choice (condition, problem type); preselect only safe defaults.
