Pattern

Navigation and page structure

One top bar, one page header, one main column. Categories live in the top bar, account areas in tabs, and depth is shown with breadcrumbs only where pages nest.

Overview

Every member page has the same skeleton: skip link, top bar, an optional banner, the page header (h1, subtitle, actions), the content, and the footer. Admin pages swap the top bar for the admin variant (red Admin tag, Queue and Audit log) and drop the footer. Auth pages centre a narrow card under the large logo.

States

  • Current page: top-bar links and tabs use aria-current="page" and the 3px red bar; nothing else is red.
  • Guest: avatar becomes Sign in; Sell still shows and leads to sign-in.
  • Unverified or suspended: a banner sits above the top bar on every page until resolved.
  • Admin: the shell changes so administrators always know they are acting as staff.
  • Back: browser back always works; dialogs and sheets do not add history entries; filters and search update the URL so back restores them.

Accessibility

  • Landmarks: header, nav with distinct aria-labels (Primary, Account, Footer), one main, footer.
  • The skip link is the first focusable element and jumps to #main.
  • One h1 per page, in the page header; sections use h2.
  • The menu button has aria-expanded and aria-controls; the sheet traps focus and returns it on close.
  • Page titles follow Page · 12L so tabs and history are distinguishable (WCAG 2.4.2).

Content

  • Nav labels are single nouns: Shoes, Purchases, Payouts. The email settings tab is Emails to stay short.
  • Page h1 matches the nav label that led there.
  • Subtitles give a count or a state, not a description: 5 orders, Read-only · kept for 2 years.
