Pattern

Forms

How 12L asks for information: one column, labels above, errors after the first submit, a summary that links to every problem, and a busy button that keeps the layout still.

WCAG 2.2 AA

Overview

Every 12L form follows one shape so a member who has signed up, listed an item and checked out never has to relearn it. It is built from form field, text field, select, checkbox, radio group, file upload and form layout, with alert for the error summary and button for the actions.

  • One column, labels above fields. Pairs that belong together (City + State, ZIP + Country, Condition + Price) share a .form-row from 640px.
  • Ask only what is needed. The sell form has no size input at all: picking a category shows the fixed size (men’s US 12 or L).
  • Validate on submit first, then re-validate each field as it changes, so members are not scolded while typing.
  • Never lose input. Server errors keep every value and add a reference (Ref 0c4e-7b21).
  • One primary action, last in the actions row: List item, Join 12L, Pay $94.00.

Validation timing

  • On first submit: validate everything, render the summary and every inline error at once, move focus to the summary.
  • After that: re-validate a field on input (clear the error as soon as it is fixed) and on blur (add it back if it breaks again).
  • Never validate on the first blur of an untouched field, and never disable the submit button to signal invalid input.
  • Server-only checks (That display name is taken) return in the same summary and inline format.

Responsive behaviour

  • Forms are one column at every width; .form-row pairs split into two columns from 640px.
  • Long forms cap at 44rem (.page--form) and auth forms at 24rem so lines stay readable on desktop.
  • On phones the primary button is full width and large; on the sell form the actions row sticks to the bottom (.form-actions--sticky).
  • Numeric fields set inputmode (numeric for ZIP, decimal for price) and autocomplete so phones show the right keyboard and autofill.

Accessibility

  • Every control has a visible <label for>; help and errors are joined with aria-describedby. Groups of checkboxes or radios sit in a <fieldset> with a <legend>.
  • Forms use novalidate so 12L’s messages replace the browser’s; errors are text plus an icon, never colour alone.
  • The error summary is announced (role="alert") and focused; links move focus to the field (WCAG 3.3.1, 3.3.3).
  • Required fields are the default; optional ones say (optional). Nothing relies on an asterisk.
  • Busy buttons keep their name and set aria-busy; read-only fields stay in the tab order.
  • Re-entering information is avoided (WCAG 3.3.7): the saved address is preselected at checkout, the email is prefilled after a failed sign-in.
  • Authentication allows paste and password managers (WCAG 3.3.8): no copy blocking, autocomplete on every credential field.

Content

  • Labels are nouns (Display name, Street address); help text states the rule (3–30 letters, numbers, _ or -. Shown publicly.).
  • Errors say what to do, not what went wrong: Enter a 5-digit ZIP code, Choose a rating, Title must be 5 to 80 characters.
  • The summary title is Fix these to continue, or names the problem when there is one (Check the price range).
  • Server errors: what failed, what to do, a reference: Couldn’t create your account. Try again in a moment. Ref 0c4e-7b21.
  • See content and tone for verbs and numbers.
