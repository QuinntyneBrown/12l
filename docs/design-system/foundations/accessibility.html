Foundation

Accessibility

Every component and token in this system is designed to meet WCAG 2.2 AA in both themes. These are the commitments a 12L screen keeps, and how to check them.

Tokens: tokens/tokens.css

Overview

Accessibility is part of each component's definition, not a review step. Every component page documents its role and pattern, keyboard map, focus behaviour, labelling, live contrast pairs, motion and touch targets.

Commitments

  • 1.1.1 Product photos have alt text naming brand and item; decorative icons are hidden.
  • 1.3.1 Structure is in the markup: landmarks, one h1, headings in order, lists, tables with captions and scope, fieldsets with legends.
  • 1.4.1 Colour is never the only signal: statuses have words, errors have icons and text, the current page has a bar and aria-current.
  • 1.4.3 Text is at least 4.5:1; 1.4.11 control edges, focus rings and meaningful icons at least 3:1, in both themes (checked by check_contrast.py).
  • 1.4.4 / 1.4.10 / 1.4.12 Text resizes to 200%, reflows at 320px and survives text-spacing overrides.
  • 2.1.1 Everything works with a keyboard; there are no keyboard traps (dialogs trap focus but close with Esc).
  • 2.4.1 A skip link is the first focusable element on every page.
  • 2.4.3 Focus order follows reading order; dialogs move focus in and return it to the trigger.
  • 2.4.7 / 2.4.11 A 2px focus ring with a 2px offset is always visible and never hidden by sticky bars.
  • 2.5.8 Targets are at least 24×24px; primary touch targets are 44px.
  • 3.3.1 / 3.3.3 Errors are described in text next to the field and summarised at the top of long forms with links to each field.
  • 3.3.7 / 3.3.8 Checkout never asks for the same information twice; sign-in allows password managers and paste.
  • 4.1.2 Custom controls expose name, role and state: aria-pressed, aria-expanded, aria-selected, aria-current, aria-invalid, aria-busy.
  • 4.1.3 Status messages (toasts, form saves, timers) use polite live regions; errors use role="alert".

Focus

One ring everywhere: outline: var(--focus-ring-width) solid var(--color-focus-ring) with var(--focus-ring-offset), shown on :focus-visible only. Inputs draw it at 0 offset over their border. On inverse surfaces (toasts, consent) the ring switches to --color-fg-inverse.

Testing procedure

  1. Run check_contrast.py and check_design_system.py; both exit 0.
  2. Tab through the page: every control is reachable, the order makes sense, the ring is always visible.
  3. Operate every component with the keys in its keyboard map.
  4. Zoom to 200% at 1280px and view at 320px: nothing overlaps or scrolls sideways.
  5. Turn on reduced motion and forced colours; check focus and borders remain visible.
  6. Listen with a screen reader (VoiceOver or NVDA): names, roles, states, live regions and dialog titles are announced.
  7. Switch to dark and repeat the contrast spot checks.

The component contract

A component is ready when its page documents, and its CSS provides:

  • Native element first; ARIA only where HTML has no equivalent, following the named WAI-ARIA APG pattern.
  • Every state reachable by attribute (disabled, aria-*), not by class alone.
  • Visible focus, 24px targets, labels that match the visible text (2.5.3).
  • Every colour pairing listed in contrast-pairs.json.
  • Motion through duration tokens, so reduced motion applies automatically.
