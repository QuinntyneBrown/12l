Foundation

Layout

Mobile first, five breakpoints, a 4/8/12-column grid, and a 1216px container. Most 12L pages are one generous column; the grid earns its keep in the catalog and the listing detail.

Tokens: tokens/tokens.css

Overview

Layout tokens grow with the viewport: --layout-columns, --layout-gutter and --layout-margin are redefined at 768px and 1024px, so a component that reads them adapts without its own media queries.

NameMin widthWhat changes
base0One column, 16px margins, top-bar menu button, bottom-sheet dialogs, sticky buy bar.

md8 columns; top-bar category nav and Sell link appear; listing grid 3-up; panels pad 32px.

xlCatalog grid with filters goes 4-up.
2xlNothing new: content stays at the container max and margins grow.

Media queries cannot read custom properties, so components.css writes the same values literally (min-width: 48rem). The mocks used 36rem, 62rem and 75rem in places; they were normalised to 40rem, 64rem and 80rem (see the README drift log).

Container and measure

  • .container caps content at --layout-container-max (1216px) and pads it with --layout-margin.
  • .page--form caps forms at 44rem; .page--narrow caps confirmations at 40rem; .auth-card caps sign-in at 24rem.
  • Prose is capped at --layout-measure (65ch).
  • The top bar is --layout-topbar-height (64px) and sticky; sticky sidebars offset themselves by it.

Usage

  • Build mobile first: write the base layout, then add min-width queries.
  • Never put two columns side by side below 1024px except the 2-up listing grid and form rows from 640px.
  • Sticky elements (top bar, filters, detail info, buy bar, form actions) use --z-sticky and must not cover focused content (2.4.11): leave scroll padding for them.
