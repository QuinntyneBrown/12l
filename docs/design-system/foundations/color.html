Foundation

Color

Three colours from the logo carry the brand: ink, paper and one signal red. Everything else is a warm grey or a status tint, and every pairing is checked for WCAG 2.2 AA in both themes.

Tokens: tokens/tokens.css

Overview

12L is ink on paper. Primary actions are solid ink (the logo's black), the canvas is warm paper, and secondary text and control edges come from a warm stone grey so nothing turns blue-grey. Signal red, the logo's L, is an indicator only: the logo, the current-page bar, the active timeline step, the hero's last words and the admin tag. It is never body text and never an error colour; errors use the separate red status ramp.

Colours are used through semantic tokens (--color-*). Components never read a --palette-* primitive, so the dark theme only has to remap roles.

Both themes

Dark is not inverted light. Surfaces get lighter as they rise (ink-950 canvas, ink-900 surface, ink-850 raised), the accent flips to paper with an ink label, and status backgrounds become deep tints with light text.

Usage

  • Ink for primary actions, links, selected chips and checked controls. One ink primary button per screen.
  • Signal red for indicators only: the logo, the current page, the current order step, the admin tag, one emphasised word in the hero. Never for text, never for errors, never for buttons.
  • Stone greys for secondary text (--color-fg-muted), metadata and placeholders (--color-fg-subtle) and control edges (--color-border-strong).
  • Status ramps only for status: success for completed and paid out, warning for reserved and flaws, info for shipped and neutral notices, danger for errors and destructive actions.
  • Never place text on a photo backdrop; use a size tag or stamp, which bring their own background.
  • To add a brand theme, add a [data-theme="name"] block that overrides semantic tokens only, then add its pairs to contrast-pairs.json and run the checker. See theming.
