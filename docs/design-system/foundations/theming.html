Theming

Light and dark from one token file. Themes override semantic tokens only; components and pages never know which theme they are in.

Tokens: tokens/tokens.css
  • Overview
  • Token tiers
  • Adding a theme
  • Re-skinning one surface
  • User preferences
  • tokens.json
  • Do and don't

Overview

Light is :root. Dark applies with data-theme="dark" on <html> or any container, and automatically when the OS prefers dark and the page hasn't forced data-theme="light". Each theme sets color-scheme so native controls and scrollbars follow.

Token tiers

TierPrefixExampleWho reads it
Primitive--palette-*, --font-*--palette-ink-950: #0b0b0bOnly semantic tokens
Semantic--color-*, --text-*, --space-*, …--color-accent: var(--palette-ink-950)Components and pages; themes override this tier
Component--btn-*, --field-*, --alert-*, --card-*, --chip-*, --toast-*, --dialog-*--btn-bg: var(--color-accent)One component; declared in components.css

Changing the brand hue touches primitives; changing what "accent" means touches semantic tokens; changing how buttons look touches component tokens.

Adding a theme

[data-theme="partner"] {
  --color-accent: var(--palette-blue-700);
  --color-accent-hover: var(--palette-blue-500);
  --color-fg-on-accent: var(--palette-white);
  --color-focus-ring: var(--palette-blue-700);
  color-scheme: light;
}
  • Override semantic tokens only; never a component class.
  • Add the theme's pairs (or run the existing list against it) with scripts/check_contrast.py; every pair must pass.
  • Regenerate tokens.json with scripts/tokens_to_json.py.
  • Keep the two dark blocks in tokens.css identical; the OS-preference block is a copy.

Re-skinning one surface

To change a component on one surface, override its component tokens there. The cookie consent does this to put buttons on an inverse surface:

.consent .btn { --btn-bg: transparent; --btn-fg: var(--color-fg-inverse); --btn-border: var(--color-border-inverse); }

User preferences

  • prefers-contrast: more raises default borders to strong and muted text to default.
  • forced-colors: active hands the focus ring and borders to system colours; buttons, inputs, cards, chips and badges draw a CanvasText border.
  • prefers-reduced-motion zeroes durations; see motion.

tokens.json

tokens/tokens.json is a W3C Design Tokens (DTCG) export: --color-bg-canvas becomes color.bg.canvas, single var() references become aliases ({palette.paper.50}), and the dark theme lives under $extensions. Use it to generate Angular SCSS maps, .NET constants for email templates, or native colour assets. Regenerate it whenever tokens.css changes:

python .claude/skills/extracting-design-systems/scripts/tokens_to_json.py docs/design-system/tokens/tokens.css
